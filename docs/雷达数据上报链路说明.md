# 雷达数据上报链路说明

本文整理当前固件中雷达数据从 UART 输入、算法处理，到 MQTT 云端与 InfluxDB 的上报链路。重点说明：部分睡眠数据会经过本地睡眠算法生成算法结果；当雷达原始睡眠数据与算法睡眠数据冲突时，当前上报侧按“算法结果优先，雷达原始数据兜底”的规则处理。

## 1. 总体链路

```text
R60ABD1 雷达
  |
  | UART 帧
  v
uartProcessTask / parseR60ABD1Frame
  |
  | 更新全局 sensorData（雷达原始解析结果）
  |
  +--> vitalDataQueue --> vitalSendTask --> InfluxDB daily_data
  |
  +--> sleepAnalysisTask --> sleepAnalysisSnapshot（睡眠算法结果）
  |
  +--> mqttTask --> MQTT daily / sleep / heartbeat
  |
  +--> sendSleepDataToInfluxDB --> InfluxDB sleep_data
```

核心对象：

| 对象 | 位置 | 含义 |
|---|---|---|
| `sensorData` | `include/radar_manager.h`, `src/radar_manager.cpp` | 雷达原始解析结果，全局缓存 |
| `VitalData` | `include/radar_manager.h` | 从 `sensorData` 拷贝出的生命体征发送快照，用于 InfluxDB daily 数据 |
| `sleepAnalysisSnapshot` | `include/radar_manager.h`, `src/tasks_manager.cpp` | 本地睡眠算法输出快照 |
| `publishPropertyReport()` | `src/mqtt.cpp` | MQTT 属性上报统一封装，协议框架不在字段取值逻辑中修改 |

## 2. 雷达原始数据入口

雷达 UART 数据由 `uartProcessTask` 读取，完整帧交给 `parseR60ABD1Frame()` 解析。解析结果写入全局 `sensorData`。

主要解析来源：

| 控制字 | 代码常量 | 主要字段 |
|---|---|---|
| `0x80` | `CTRL_PRESENCE` | `presence`, `motion`, `body_movement`, `distance`, `pos_x/y/z` |
| `0x81` | `CTRL_BREATH` | `breath_status`, `breath_rate`, `breath_waveform[]` |
| `0x85` | `CTRL_HEARTRATE` | `heart_rate`, `heart_waveform[]` |
| `0x84` | `CTRL_SLEEP` | `bed_status`, `sleep_state`, `sleep_score`, `sleep_total_time`, `awake_time`, `light_sleep_time`, `deep_sleep_time`, `awake_ratio`, `light_sleep_ratio`, `deep_sleep_ratio`, `turn_count`, `turnover_count`, `avg_breath_rate`, `avg_heart_rate`, `apnea_count` |

说明：

- `sensorData` 表示雷达原始解析结果，不应被算法结果直接覆盖。
- 当前代码中睡眠算法结果写入 `sleepAnalysisSnapshot`，发送端按优先级选择字段值。

## 3. 睡眠算法链路

`sleepAnalysisTask()` 周期性读取 `sensorData` 中的心率、呼吸率、体动、床状态等数据，并调用 `SleepAnalyzer`。

算法输入主要来自：

| 算法输入 | 来源 |
|---|---|
| 心率 | `sensorData.heart_rate` |
| 呼吸率 | `sensorData.breath_rate` |
| 体动 | `sensorData.body_movement` |
| 床状态 | `sensorData.bed_status` |
| HRV 等派生指标 | 睡眠/情绪任务各自的 `PhysioDataProcessor` 根据心率/呼吸率计算 |

算法输出通过 `updateSleepAnalysisSnapshot()` 整包写入 `sleepAnalysisSnapshot`：

| 字段 | 含义 |
|---|---|
| `algorithm_state` | 算法睡眠状态 |
| `current_sleepiness` | 当前困倦度 |
| `total_sleep_time` | 总睡眠时长 |
| `deep_sleep_time` | 深睡时长 |
| `light_sleep_time` | 浅睡时长 |
| `rem_sleep_time` | REM 时长 |
| `awake_time` | 清醒时长 |
| `out_of_bed_time` | 离床时长 |
| `sleep_latency` | 入睡潜伏期 |
| `wake_count` | 醒来次数 |
| `sleep_cycles` | 睡眠周期数 |
| `duration_score` 等评分字段 | 睡眠质量各维度评分 |
| `updated_at` | 算法快照更新时间 |
| `valid` | 算法快照是否有效 |

当 `getFreshSleepAnalysisSnapshot()` 返回 true 时，说明已有可用且未过期的算法结果。MQTT 和 InfluxDB 会在临界区内复制一份完整快照，后续构包只使用本地副本；快照超过 `SLEEP_ANALYSIS_SNAPSHOT_TTL_MS`（当前 15 秒）后会回退到雷达原始睡眠数据。

## 4. MQTT 云端上报

MQTT 上报统一通过 `publishPropertyReport()` 封装，协议框架如下：

```json
{
  "id": "message id",
  "method": "thing.event.property.post",
  "params": {
    "deviceId": "device name",
    "reportType": "daily/sleep/heartbeat"
  }
}
```

上报主题格式：

```text
/sys/{productKey}/{deviceName}/s/event/property/post
```

注意：当前修改只影响 `params` 内睡眠字段的取值，不改变 MQTT topic、method、外层 JSON 结构、`deviceId`、`reportType` 等云端协议框架。

### 4.1 MQTT daily

函数：`sendDailyDataToMQTT()`

触发：`mqttTask()` 中有人且到达 `DAILY_DATA_INTERVAL`。

字段来源：主要使用雷达原始 `sensorData`，并追加有效期内的情绪分析字段。

主要字段：

```text
heartRate, breathingRate, personDetected, humanActivity,
humanDistance, sleepState, humanPositionX/Y/Z,
heartbeatWaveform, breathingWaveform,
abnormalState, bedStatus, struggleAlert, noOneAlert,
wifiIP,
primaryEmotion, secondaryEmotion, emotionConfidence,
emotionIntensity, emotionValence, emotionArousal,
stressLevel, anxietyLevel, relaxationLevel
```

### 4.2 MQTT sleep

函数：`sendSleepDataToMQTT()`

触发：

- `mqttTask()` 周期调用。
- `sleepAnalysisTask()` 检测到会话结束时调用，并在 InfluxDB 与 MQTT 均发送成功后才标记本次报告已发送；重试时只补发尚未成功的一侧。

发送前判断：

- 如果 `getFreshSleepAnalysisSnapshot()` 返回 true，按复制出的算法状态判断是否需要上报睡眠数据。
- 周期上报只允许算法状态 3/4/5；`SLEEP_SESSION_END(8)` 只允许会话结束路径显式上报，避免周期任务重复发送结束报告。
- 如果算法快照无效，回退到原来的雷达 `sensorData.sleep_state` 判断。

冲突字段优先级：

| MQTT 字段 | 算法有效时来源 | 算法无效时来源 |
|---|---|---|
| `sleepQualityScore` | `sleepAnalysisSnapshot.total_score` 四舍五入 | `sensorData.sleep_score` |
| `sleepState` | `sleepAnalysisSnapshot.algorithm_state` | `sensorData.sleep_state` |
| `totalSleepDuration` | `sleepAnalysisSnapshot.total_sleep_time` | `sensorData.sleep_total_time` |
| `awakeDuration` | `sleepAnalysisSnapshot.awake_time` | `sensorData.awake_time` |
| `lightSleepDuration` | `sleepAnalysisSnapshot.light_sleep_time` | `sensorData.light_sleep_time` |
| `deepSleepDuration` | `sleepAnalysisSnapshot.deep_sleep_time` | `sensorData.deep_sleep_time` |
| `outOfBedDuration` | `sleepAnalysisSnapshot.out_of_bed_time` | `sensorData.bed_Out_Time` |

雷达保留字段：

```text
sleepQualityGrade,
awakeDurationRatio, lightSleepRatio, deepSleepRatio,
outOfBedCount, turnCount,
avgBreathingRate, avgHeartRate,
apneaCount, abnormalState, bodyMovement, breathStatus,
largeMoveRatio, smallMoveRatio,
struggleAlert, noOneAlert
```

算法附加字段保留原协议字段集合：

```text
algorithmState, algorithmSleepiness,
algoTotalSleepTime, algoDeepSleepTime, algoLightSleepTime,
algoRemSleepTime, algoAwakeTime, algoOutOfBedTime,
algoSleepLatency, algoWakeCount, algoSleepCycles,
algoDurationScore, algoDeepScore, algoContinuityScore,
algoPhysiologyScore, algoLatencyScore, algoEfficiencyScore,
algoCycleScore, algoTotalScore,
algoCycleCount, algoInDeepPhase, algoInRemPhase
```

这些 `algo*` 字段是额外算法明细，不改变 MQTT 外层协议。

### 4.3 MQTT heartbeat

函数：`sendHeartbeatToMQTT()`

触发：无人或心率/呼吸率都为空时按 `HEARTBEAT_INTERVAL` 上报。

主要字段：

```text
personDetected=0,
heartbeat=1,
timestamp,
sleepState,
noOneAlert,
wifiIP
```

## 5. InfluxDB 上报

InfluxDB 写入通过 HTTP `/api/v2/write` 完成。当前有两个 measurement：

```text
daily_data
sleep_data
```

### 5.1 InfluxDB daily_data

函数：`sendVitalDailyDataToInfluxDB()`

字段来源：`VitalData`，由 `uartProcessTask()` 从 `sensorData` 拷贝而来。

当前字段：

```text
heartRate,
breathingRate,
personDetected,
humanActivity,
bodyMovement,
humanDistance,
humanPositionX,
humanPositionY,
humanPositionZ,
heartbeatWaveform,
breathingWaveform,
bedStatus
```

去重策略：

- `daily_data` 只保留实时生命体征、存在/活动、位置和波形类数据。
- 已移除睡眠统计/告警类重复字段：`sleepState`, `abnormalState`, `struggleAlert`, `noOneAlert`。
- 这些字段归入 `sleep_data` 管理，避免 InfluxDB 内部重复写。

### 5.2 InfluxDB sleep_data

函数：`sendSleepDataToInfluxDB()`

触发：
- `vitalSendTask()` 周期检查，当前间隔 5 秒。
- `sleepAnalysisTask()` 检测到会话结束时调用。
- 启动时 WiFi 已连接会尝试调用一次，但不满足睡眠态时不会实际写入。

发送前判断：
- 如果 `getFreshSleepAnalysisSnapshot()` 返回 true，周期写入只允许算法状态 3/4/5。
- `SLEEP_SESSION_END(8)` 只允许会话结束路径显式写入，避免周期任务重复写结束报告。
- 如果没有新鲜算法快照，则回退判断雷达 `sensorData.sleep_state == 0 || sensorData.sleep_state == 1`。

tag：

```text
deviceId={macAddress}
dataType=sleep
source=algorithm 或 source=radar
```

冲突字段优先级：

| InfluxDB 字段 | 算法有效时来源 | 算法无效时来源 |
|---|---|---|
| `sleepQualityScore` | `sleepAnalysisSnapshot.total_score` 四舍五入 | `sensorData.sleep_score` |
| `sleepState` | `sleepAnalysisSnapshot.algorithm_state` | `sensorData.sleep_state` |
| `totalSleepDuration` | `sleepAnalysisSnapshot.total_sleep_time` | `sensorData.sleep_total_time` |
| `awakeDuration` | `sleepAnalysisSnapshot.awake_time` | `sensorData.awake_time` |
| `lightSleepDuration` | `sleepAnalysisSnapshot.light_sleep_time` | `sensorData.light_sleep_time` |
| `deepSleepDuration` | `sleepAnalysisSnapshot.deep_sleep_time` | `sensorData.deep_sleep_time` |
| `outOfBedDuration` | `sleepAnalysisSnapshot.out_of_bed_time` | `sensorData.bed_Out_Time` |

算法有效时额外写入：

```text
remSleepDuration,
sleepLatency,
wakeCount,
sleepCycles,
sleepiness,
durationScore,
deepScore,
continuityScore,
physiologyScore,
latencyScore,
efficiencyScore,
cycleScore,
inDeepPhase,
inRemPhase
```

算法无效时不会写这些算法专属字段。

始终来自雷达的数据：

```text
sleepQualityGrade,
awakeDurationRatio,
lightSleepRatio,
deepSleepRatio,
outOfBedCount,
turnCount,
avgBreathingRate,
avgHeartRate,
apneaCount,
abnormalState,
breathStatus,
largeMoveRatio,
smallMoveRatio,
struggleAlert,
noOneAlert
```

## 6. 冲突处理总规则

当前规则可以概括为：

```text
如果字段是睡眠统计/状态/评分类，并且算法有对应输出：
    使用 sleepAnalysisSnapshot
否则：
    使用雷达原始 sensorData
```

适用字段：

```text
sleepQualityScore,
sleepState,
totalSleepDuration,
awakeDuration,
lightSleepDuration,
deepSleepDuration,
outOfBedDuration
```

不适用字段：

- 心率、呼吸率、平均心率、平均呼吸率、呼吸暂停次数、体动比例、告警等，当前仍以雷达原始数据为准。
- MQTT 外层协议字段不参与该规则，例如 `id`, `method`, `deviceId`, `reportType`。
- InfluxDB 的 `deviceId`, `dataType`, `source` 是 tag，不属于雷达/算法冲突字段。

## 7. 触发时机汇总

| 任务/函数 | 触发方式 | 输出 |
|---|---|---|
| `uartProcessTask()` | UART 收到完整雷达帧 | 更新 `sensorData`，发送 `VitalData` 到队列 |
| `vitalSendTask()` | 从 `vitalDataQueue` 收到数据 | 写 InfluxDB `daily_data`，周期写 `sleep_data` |
| `sleepAnalysisTask()` | 每秒处理一次生理/体动数据 | 更新 `sleepAnalysisSnapshot`；会话结束时触发 sleep 上报 |
| `mqttTask()` | MQTT 常驻任务 | 上报 daily、sleep、heartbeat |
| `sendSleepDataToMQTT()` | MQTT 周期或会话结束 | MQTT `reportType=sleep` |
| `sendSleepDataToInfluxDB()` | 周期、启动时、会话结束 | InfluxDB `sleep_data` |

## 8. 注意事项

1. `sleepAnalysisSnapshot` 通过 `updated_at` 和 `SLEEP_ANALYSIS_SNAPSHOT_TTL_MS` 做新鲜度判断；超过 15 秒未更新时发送端会回退到雷达原始睡眠数据。
2. `sensorData` 应保持雷达原始解析结果，不建议在算法任务中直接覆盖。
3. MQTT 的 topic、method、外层 JSON 和 `deviceId/reportType` 属于云端协议框架，不应随字段优先级调整而修改。
4. InfluxDB 的 `source` tag 用于区分睡眠行当前采用的主数据来源，MQTT 中没有新增该字段，以避免影响云端协议。
5. 算法与雷达字段单位按当前代码原样透传；如果后续统一单位，应同时更新本文档和云端/数据库消费逻辑。
